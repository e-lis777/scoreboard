# Табло ФК «Легион»

Версия 4 использует два понятных режима:

- `manual` — счёт, таймер и автор гола вводятся вручную;
- `kimberly_full` — Kimberly управляет счётом, соперником и событиями голов, а оператор всегда управляет таймером и таймом.

Цель — один эфирный оверлей, который мгновенно реагирует и на Kimberly, и на ручные действия. Kimberly — главный источник там, где у неё есть данные; ручной пульт — резерв и дополнение, а не второй конкурирующий источник.

Выбор матча показывает общее расписание «Легион 2017 Green» (`team_id = 17986`) и «Легион 2017 Blue» (`team_id = 17987`). Game ID оператор не вводит: выбранный матч закрепляется, а во время игры данные обновляются каждые две секунды.

## Запуск

Требуется Node.js 20 или новее.

```powershell
npm start
```

После запуска:

- оверлей: `http://127.0.0.1:4173/legion.html`;
- управление: `http://127.0.0.1:4173/legion.html?admin=true`.

Локальный сервер нужен из-за CORS-ограничений Kimberly. Он доступен только с этого компьютера, принимает только безопасные GET-запросы и разрешает три заранее заданных маршрута API.

## Локальное управление и Firebase

Входа в интерфейсе нет: адрес админки открывает пульт сразу. Локальный сервер, привязанный к `127.0.0.1`, выполняет служебный вход в Firebase в фоне, поэтому правила Firebase по-прежнему не открываются для посторонней записи.

Учетные данные хранятся только на рабочем компьютере в `server/local-auth.json`; файл исключён из Git. При переносе проекта на другой компьютер создайте в нём JSON следующего вида:

```json
{ "email": "оператор@example.com", "password": "пароль Firebase" }
```

В Firebase должны быть включены Email/Password и правило доступа для UID этого пользователя в `/admins/UID = true`. Правила находятся в `database.rules.json`.

## Архитектура

- `legion.html` — разметка и оформление оверлея/панели;
- `src/app.js` — управление интерфейсом, Firebase и синхронизацией;
- `src/kimberly-client.js` — read-only клиент локального шлюза и выбор матча;
- `src/match-mode.js` — чистая нормализация матча и политика режимов;
- `server/index.mjs` — локальная раздача файлов, ограниченный шлюз Kimberly и фоновое локальное подключение пульта;
- `test/` — тесты нормализации, голов и выбора матча;
- `database.rules.json` — правила доступа Firebase Realtime Database.

## Ограничения Kimberly

В приложение разово импортированы актуальные составы «Легион 2017 Green» (`17986`) и «Легион 2017 Blue» (`17987`). Они доступны на любом устройстве и используются как резерв для карточек голов. Событие матча Kimberly остаётся главным источником автора, номера, минуты и фотографии.

В разделе «Состав» по-прежнему можно импортировать обновлённый CSV/JSON для выбранной команды. Такой импорт хранится локально и имеет приоритет над встроенным снимком.

Логотип соперника автоматически берётся из профиля команды. Любая эмблема помещается в нейтральную тёмную плашку с `object-fit: contain`, поэтому белый или необрезанный фон не ломает композицию. При отсутствии логотипа используется спокойная заглушка-мяч.

Таймер и тайм всегда ведёт оператор: данные Kimberly по времени могут отсутствовать или запаздывать. Для счёта и соперника доступна явная ручная коррекция; пока она включена, последующие ответы Kimberly её не перезаписывают. Карточки показываются и для Легиона, и для соперника; без данных игрока используется название и логотип команды.

## Larix Broadcaster

Для Larix есть два отдельных web-overlay:

- `larix.html?mode=standby` — ожидание эфира: метка Kimberly, турнир, команды, дата, место и обратный отсчёт; во время игры и после финала показывается счёт;
- `larix.html?mode=pause` — пауза: «Перерыв» при соответствующем статусе или «Техническая пауза», с текущим счётом и таймом.

Обе страницы рассчитаны на полный кадр 16:9, получают состояние через `/api/match` и не требуют открытой админки.
